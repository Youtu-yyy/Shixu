# 从对话整理的重点回归测试集

本测试集按每次改进的**最终要求**建立，而非把历史中间方案全部当成正确结果。新增的机器案例有固定编号、输入和人工明确的期望；原有的核心与 Android 测试继续保留。主要示例使用虚构事项和教室，私人照片不复制入测试目录或公开教学。

## 文件和运行

- [history-cases.tsv](history-cases.tsv)：56 条可执行语料，覆盖相对时间、时段之前、日期前归属、时间段、优先级、地点、通知、批量候选与非法输入。
- [acceptance-cases.tsv](acceptance-cases.tsv)：47 条界面、通知、组件、图片、隐私与升级验收记录，包含具体操作、通过标准、已有自动入口和执行状态；1.0.8 增加持续提醒、独立开关和振动等级。
- `tests/HistoryRegressionTests.java`：执行数据集，每条失败显示编号和期望差异，汇总全部案例再报错。
- `test-regression.ps1`：统一入口。每次先运行全部核心测试，再按选择执行 Android 分组。未选择的分组与人工项目不计为通过。

在项目根目录的 PowerShell 7 运行：

```powershell
# 无需模拟器，运行原有核心断言及新增语料
./test-regression.ps1

# 有模拟器时，额外验证指定重点（将覆盖安装测试版，保留主应用数据）
./test-regression.ps1 -DeviceGroups BeforeDay,Inline,Ocr,Batch

# 验证构建好的、匹配模拟器架构的精简包
./test-regression.ps1 -DeviceGroups BeforeDay,Ocr,WidgetPreview -AppApk F:/codex/app/Shixu/build/Shixu-release-emulator.apk

# 已有专项：进程退出、锁屏、深度休眠模拟
./test-background.ps1
```

设备分组支持：BeforeDay、SameTime、Notice、Inline、Snooze、Week、WidgetPreview、Widget、Tutorial、Settings、Ocr、Batch、Alert。`Alert` 会短时测试响铃，验证持续提醒和停止逻辑；模拟器无法验证实际振动手感。`Widget` 需要先将组件添加到模拟器桌面。设备脚本会安装测试辅助包、创建和清理测试事项；后台脚本也会短时改变模拟器电池/休眠状态后恢复。不向已连接的个人真机自动批量写入任务。

图片增强 `./test-device.ps1 -EnhanceOnly`、购票截图 `-TicketOnly` 依赖手动放入应用测试目录的照片，不放入默认必跑组；未提供照片应记为未执行，而不是通过。现有 Ocr/Batch 分组使用自绘通知与表格，可独立运行；它们不替代对拍照模糊、透视、低对比度真实照片的验收。

结果在 `build/regression/`：`history-results.md` 与 JSON 含逐案例结果；`core.log` 含现有核心组结果；选择设备分组后另有对应日志；`suite-results.json` 列出本次所选组。再次运行会覆盖这些结果，长期对比前应保存副本。验收表中的状态是本次建立测试集时的状态，后续运行设备组后需填写实际设备与结果。

## 时间基准和判定

新增语料统一使用 **2026-10-22 10:00，Asia/Shanghai**，忽略执行当天真实日期。空值如 `time=` 表示必须为空；`trigger` 比较实际计划触发时刻；`noteSource=true` 要求备注与完整输入逐字相同。多事项使用 `0.time` 等检查每项字段。优先级存储值为高 0、中 1、低 2。

这是模型/规则层测试：直接传入文本并检查解析结果，不等同于“通知真的弹出”或“OCR 图片真的识别正确”。设备测试仍使用设备真实时钟，其通知发送和权限检查不能用固定的语料时钟替代。

## 对话重点与覆盖对应

| 迭代重点 | 最终验收要求 | 对应测试 |
|---|---|---|
| 中文分钟数漏识别 | 二十分钟后/半小时后以输入时刻计算；相对提醒默认准时 | REL-01～05、CoreTests |
| 今天下午不自动提醒 | 有效时间默认开启，普通事项默认提前30分钟，尊重明确关闭 | REM-01～05、InlineOnly |
| 时段前的提前量 | 晚上前→下午13:30，中午前→上午09:00；前缀提醒我/请不能破坏识别 | DUE-01～07、BeforeDayOnly |
| 某天前应前一天完成 | 11月7日前归11月6日；标题保留7日前；默认6日18:30提醒；不能二次提前 | DUE-08～13、BeforeDayTests、BeforeDayOnly |
| 同一时刻表达 | 明天的这个时候按明天当前时刻；无事由提供定时提醒 | REL-06～07、SameTimeOnly |
| 全角冒号与短横线 | 14：00-20：00等整体识别区间，不把结束时间漏进标题 | RNG-01～07、CoreTests |
| 通知自动提炼 | 提取主要事项、时间、地点；备注直接保留原文；不确定或取消通知不乱提醒 | LOC、NOT、NoticeTests、NoticeOnly |
| 图片与多事件 | 本机OCR→可编辑文字→多选候选→共享编辑→只保存所选；单区间不拆成两个事件 | MUL、BATCH、OcrOnly、BatchOnly |
| 表单与提醒统一 | 分类/优先级下拉；提醒在编辑页开关控制；没有独立提醒弹窗 | UI-01～05、InlineOnly |
| 排序规则与标记 | 按开始时间而非提醒时间；同时间比优先级，反向同理；默认低；标签显示优先级颜色 | PRI、SORT、CoreTests |
| 防误触完成 | 左滑后确认；完成划线、移当日末尾、取消提醒；更多菜单不重复完成 | DONE、MENU、SnoozeOnly |
| 通知操作 | 完成/10分钟后再提醒；实际计划时间、相对提前量与展示同时更新 | NOTIFY-05、SnoozeOnly |
| 后台与锁屏延迟 | 必须不打开软件测送达；记录延迟，分清划后台和强行停止 | NOTIFY-01～06、后台专项及真机 |
| 桌面组件 | 今明一起/全部两种；标题进入编辑；内嵌确认；完成保留划线；连续滚动 | WIDGET、WidgetTests、WidgetOnly |
| 组件尺寸/预览/卡死 | 字体随尺寸调整；预览足够大；重复点击更新；厂商启动器需实机验收 | WIDGET-02/06/07、WidgetPreviewOnly |
| 周视图 | 七列均宽；全天置顶；区间纵条；重叠并排；跨夜分段；标题从头显示 | WEEK、WeekTests、WeekOnly |
| 紧凑界面和教学 | 首页/日历/周头部节省空间；设置提供图片翻页教程；教学用虚构教室并说明日期前规则 | HOME、CAL、GUIDE、TutorialOnly |
| 隐私和安装体积 | 联网语音默认关；图片本机不上传；精简不删OCR或组件资源；覆盖升级保留数据 | VOICE、OCR、PKG |

明确不再要求的旧方案：前置直接完成按钮、提醒单独弹窗、按时间先后深浅着色、无事项日期自动变窄、组件上一页/下一页、组件任意位置点击均编辑、今明分成两个独立标签。后续修改不得以恢复这些旧方案来“通过”测试。

1.0.10 补充：按真机体验撤销振动强度分级，不再要求低中高振幅或强度下拉。通知仅使用原新版类别ID并更名为“事项提醒”，清理旧版“待办与日程提醒”；不得以创建新类别来重置用户在系统里的关闭或静音设置。

## 发布前的最小检查建议

改解析时运行默认集，再跑 BeforeDay/Notice/Inline 中相关分组；改 OCR 或候选编辑时跑 Ocr/Batch/Inline；改小组件跑 WidgetPreview/Widget 并完成实际启动器验收；改闹钟或稍后提醒跑 Snooze/后台专项及真机锁屏；开启代码或资源精简后用实际精简包跑 Ocr/Batch/WidgetPreview，并验证签名、架构和升级。

真机通知记录至少包含：机型、系统/启动器版本、应用版本、通知/准时提醒/自启动/电池/后台权限状态、计划时间、实际时间、延迟秒数、前台/锁屏/划后台状态。计划时刻前后操作导致的偏移不能误当作算法提前量错误；反之，打开应用后才补发也不能算后台正常送达。当前对话中报告过锁屏延迟，应继续列为真机待验收。
